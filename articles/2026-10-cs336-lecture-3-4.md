## 一、一个 Transformer 块怎样处理信息？

### 1.1 从 token 编号到下一 token 的概率

语言模型的一个基本任务是：给定前文，预测下一 token。比如输入“这门课讲的是”，模型要给出后续各个候选 token 的概率。

token 是文本切分后的单位，可能是一个字，也可能是词的一部分。模型接收的是 token 的整数编号，再通过一张可学习的表，把每个编号转换成一个向量。这一步叫embedding。表中的数值，以及后续网络中其他通过训练调整的数值，统称为模型的参数。

向量是一组有序的数，维度就是数值的个数。模型用这些数表示当前 token 的信息；训练会调整它们的计算方式，使这些表示有助于预测。

接下来，每个 token 的向量经过多层处理，逐步融入前文信息。最后，输出层为词表中的候选 token 分别打分，再把分数转换成概率：

```
文本 → token ID → 向量表示 → 多层 Transformer 块 → 候选 token 的分数 → 概率
```

原始分数叫logits，把它们转换成总和为 1 的概率的操作叫softmax。

### 1.2 两种计算：读取上下文，再加工表示

每个 Transformer 块主要包含两个子层。

第一个是自注意力。它让当前位置从其他允许访问的位置读取信息。在用于逐 token 生成的因果语言模型中，当前位置可以读取自己和前文，不能读取未来文本。

第二个是前馈网络（FFN）。它在每个位置独立加工已经混入上下文的向量。这里“独立”是说 FFN 本身不再读取其他位置；这些位置的信息已经由注意力带入了当前表示。

因此，标准块的顺序可以理解为：注意力负责位置之间的信息交换，FFN 负责每个位置内部的信息变换。重复多层后，模型就能在不断更新的表示上继续计算。

### 1.3 Q、K、V 和“多头”是什么？

注意力需要确定：当前位置应当从哪些位置读取多少信息。

为此，模型从向量中计算出三组表示：Q（query）用于发起匹配，K（key）用于参与匹配，V（value）是实际被读取的内容。当前位置的 Q 与各位置的 K 计算匹配分数，经 softmax 得到权重，再对对应的 V 加权求和。

这里的表示变换通常用矩阵乘法完成，称为线性投影：把一组输入数值按可学习的系数组合成另一组数值。“多头”是把上述匹配并行做多次。每个头都有自己的投影，可以利用完整输入的信息，学习不同的匹配方式；各头的结果最后拼接，再投影回模型主干的维度。

后文用 d_model 表示主干中每个 token 的向量长度，用 d_ff 表示 FFN 内部的中间向量长度。层数 L 表示上述块重复多少次。这三个量分别描述模型的宽度、FFN 的宽度和模型的深度。

### 1.4 残差与归一化为什么总是一起出现？

一个块还需要解决训练问题：经过很多层变换后，信息与参数更新信号能否稳定传播？

残差连接把子层的输入直接加回输出。子层因此可以学习“在已有表示上增加什么变化”。归一化则调整向量的数值尺度，避免不同层的输入幅度相差过大。

训练用一个称为损失的数值衡量预测误差，再计算“怎样调整参数才能降低损失”的信号，称为梯度。根据梯度更新参数后，模型继续做下一批预测。深层模型要把梯度逐层传回，残差与归一化的位置会直接影响这一过程。

有了这几个概念，后面的架构选择就有了共同背景：模型既要表达足够复杂的信息，也要让这条计算过程容易训练、执行高效。

## 二、怎样让这个块更稳定、更有效？

### 2.1 归一化放在哪里：pre-norm

残差连接和归一化都需要，但先后顺序可以不同。早期 Transformer 先把子层输出与输入相加，再归一化；这叫post-norm。许多现代模型先归一化输入，再计算子层，最后加回原输入；这叫pre-norm。

两者的区别在于：pre-norm 保留了一条不经过该归一化操作的直接相加路径。模型加深时，这通常更有利于梯度稳定传播，因此成为现代大模型的常见选择——课程称其为"2024 年唯一人人同意的事"。

补充｜结构对照：为什么会影响训练

用 x 表示子层输入，Norm 表示归一化，SubLayer 表示注意力或 FFN：

```
pre-norm： x + SubLayer(Norm(x))post-norm： Norm(x + SubLayer(x))
```

Xiong et al.（2020）分析了初始化时的梯度：post-norm 中靠近输出层的参数梯度可能较大，直接使用大学习率会不稳定；pre-norm 的梯度表现更平稳。这也是早期研究讨论 pre-norm 能否减少学习率预热需求的原因——预热指训练开始时先用较小学习率，再逐渐提高。

这不表示 post-norm 无法训练，或 pre-norm 永远无需预热：BERT 就采用 post-norm，课程也提到 OPT-350M 这一例外。另有模型在注意力或 FFN 的输入、输出都设置归一化；阅读这类"双重归一化"时，应看清它位于子层分支还是残差相加后的主干，不能仅凭"前""后"判断效果。

### 2.2 用哪种归一化：RMSNorm

确定位置之后，还要选择归一化的计算方法。

LayerNorm先减去向量的均值，再按标准差缩放；RMSNorm省去减均值，用均方根衡量整体幅度并缩放。两者都在控制数值尺度，RMSNorm 的步骤更少。

为什么值得省这些步骤？GPU 既要计算，也要从显存读取数据、把结果写回。FLOPs（浮点运算次数）少，不代表耗时就少：反复读写显存也会花时间。RMSNorm 简化了归一化，在许多设置中能保持与 LayerNorm 相近的效果，因此成为 Llama 等模型的选择；实际能快多少，还取决于具体实现。

线性层的bias（偏置）也属于类似的简化：它是在矩阵乘法后额外加上的一组可学习数值。许多现代模型去掉这些偏置，以减少操作与状态。

补充｜论文证据与模型对照

LayerNorm 通常还带可学习的缩放和偏置；RMSNorm 通常只保留缩放。GPT-2/3、BLOOM 使用 LayerNorm，Llama、PaLM、T5 使用 RMSNorm 或相近形式。

课程引用的 Narang et al.（2020）小模型实验中，换用 RMSNorm 后，每秒训练步数由 3.5 增至 3.68，损失也有改善；具体提速仍取决于算子实现、融合方式和硬件。课程用归一化约占 0.2% 的浮点运算量说明其算术开销小，而所引 Ivanov 等工作的画像显示，部分负载下包括归一化在内的一类访存受限操作可占约四分之一运行时间——两项数字统计范围不同，不能把后者全部视为换 RMSNorm 能省下的时间。

### 2.3 FFN 怎样加工信息：从激活函数到门控

FFN 通常先把向量变长，在更宽的中间表示上计算，再压回主干维度。中间还要有一次非线性变换：如果只有连续的线性变换，多层仍可合并成一次线性变换，表达能力会受到限制。

非线性变换常由激活函数完成。ReLU 将负值置零、保留正值；GeLU 的变化更平滑。这些都是普通 FFN 的常见选择。

门控 FFN 增加了另一条可学习分支，让两条分支的结果逐元素相乘。每个输入因而能产生不同的调制系数，缩小、放大或改变相应特征的符号。常见的SwiGLU就属于这类结构。

以四维中间结果为例，暂不展开两条分支如何算出：

```
分支 A = [ 0.73, -0.24, 2.86, 0.31]分支 B = [ 0.90,  0.20, 1.50, 0.00]相乘后 = [ 0.66, -0.05, 4.29, 0.00]  （四舍五入）
```

相对于 A，第二维的幅度缩小，第三维放大，第四维在这次计算中变为零。之后还要通过一次投影，回到主干维度。门控系数可以超过 1 或为负，不能简单理解为开关。

实验中，SwiGLU、GeGLU 等门控结构常比普通 FFN 有小幅优势。不过，门控并不是模型有效的必要条件，也不能仅凭激活函数判断模型质量。

补充｜公式，以及中间维度为什么常取 8/3 倍

```
普通：FFN(x) = σ(xW1)W2门控：FFN(x) = (σ(xW1) ⊗ xV)W2
```

W1、V、W2 是可学习矩阵，σ 是激活函数，⊗ 表示对应元素相乘。σ 取 Swish 得 SwiGLU，取 GeLU 得 GeGLU；原版 GLU 用 sigmoid 把其中一条分支限制在 0–1，SwiGLU 没有这一限制。门控结构有三个矩阵、普通结构只有两个：若普通 FFN 的中间维度为 4d，参数量约 8d²；门控把中间维度取 (8/3)d，三个矩阵同样约 8d²——在近似相同的参数量和主要计算量下比较结构。Shazeer（2020）的实验采用这种对齐；8/3 是常见比较基线，实际模型也会采用其他比例并按硬件取整。

补充｜另一种变体：注意力与 FFN 并行

标准块先计算注意力，再把更新后的表示送入 FFN；并行块让两者从同一个输入计算，最后把两份结果加回残差流（PaLM、GPT-J 等采用过）。这样可以共享部分归一化计算、融合部分矩阵乘，但也改变了信息流：FFN 在该块内没有直接读到刚算出的注意力结果。是否值得采用，需要结合模型效果与系统收益评估。

### 2.4 怎样表示顺序：RoPE

注意力的匹配分数首先来自内容，但语言还依赖顺序与距离。仅有“哪些 token 相互匹配”不够，模型还需要知道它们位于什么位置。

一种做法是给每个位置设置向量，加到输入表示中。RoPE（旋转位置编码）采用另一种方式：在注意力匹配时，让 Q、K 带上位置相关的旋转。

它希望保留的是相对距离。例如第 2 与第 3 个位置相距 1，第 200 与第 201 个位置也相距 1。若两对 Q、K 的内容相同，RoPE 使这两组匹配得到相同的位置影响；内容不同，匹配分数仍可以不同。

具体做法是把 Q、K 的维度两两配对，按位置旋转。两者做内积时，共同的位置偏移相消，位置差保留下来。RoPE 因此将相对位置信息引入注意力分数，并成为 Llama 等模型的常见选择。

这里有一个边界：RoPE 提供了表示位置的方式，并不自动保证模型能处理任意长的文本。超出训练长度后是否仍有效，还需要后续训练与位置缩放方法验证。

补充｜位置编码的几种方案与 RoPE 公式

| 方案 | 怎样引入位置 | 代表 |
| --- | --- | --- |
| 正弦位置编码 | 把预先计算的不同频率 sin/cos 加到输入表示中 | 原版 Transformer |
| 可学习绝对位置编码 | 为每个位置学习一个向量 | GPT-2/3 |
| 相对位置偏置 | 在注意力分数中加入相对距离的偏置 | T5 |
| RoPE | 按位置旋转各层注意力的 Q、K | Llama 等 |

这些是不同设计方向，并非严格依次淘汰的四代技术；因果掩码本身也带来顺序约束，不能把"没有显式位置编码"等同于"完全无法区分顺序"。对 RoPE，位置 m 在第 i 对维度上的旋转角为 mθ_i，常见基线 θ_i = 10000^(−2i/d)；其目标可写为 f_q(x, m)·f_k(y, n) = g(x, y, m−n)——右侧仍含内容 x、y，位置依赖只以 m−n 出现。不同模型会调整旋转基频与缩放方式。

## 三、模型的宽度、深度怎样选择？

前面讨论的是“块里放什么计算”，接下来讨论“这些计算做多大、重复多少次”。这类在训练前设定的配置，称为超参数。它们决定模型的容量，也影响训练与推理成本。

### 3.1 FFN 的中间表示需要多宽？

普通 FFN 常把向量从 d_model 扩到约 4 倍，再压回去。例如主干维度为 1024，中间维度就取 4096。更宽的中间表示意味着更多参数和计算。

门控 FFN 多一条分支。为了控制总参数量，中间维度常改为约 8/3 倍，也就是主干 1024 维时，中间约为 2731 维，再按实现要求取整。

这些比例提供了常用起点，实际模型并不完全一致。这里需要理解的取舍是：增加中间宽度可能改善表示能力，但也会提高每个 token 的计算成本。

### 3.2 多头注意力的维度怎样分配？

多头注意力常采用 头数 × 单头维度 = d_model。例如主干为 8192 维，可以设置 64 个头，每头 128 维。

这个等式描述的是投影后各头的总宽度。头数增加时，若总宽度固定，每个头就会变窄；因此“头更多”不等于“能力必然更强”。有些架构还会让注意力的总宽度不同于主干宽度。

到了第四部分，还会遇到另一种头数：Q 的头数与 K、V 的头数可以不同。那是在节省缓存，和这里分配表示维度的问题相关，但并不相同。

### 3.3 做宽一些，还是做深一些？

模型可以通过增加向量维度变宽，也可以通过增加块的数量变深。同样参数预算下，宽度与深度存在取舍。

宽度决定每个位置一次能处理多大的表示，深度决定这种加工重复多少轮。两者也受硬件影响：更多层会增加顺序执行的步骤，较宽的矩阵则需要足够的计算资源与设备间带宽。

课程用 d_model ÷ 层数 比较不同模型，许多配置落在约 100–200。但这个比值是一项经验观察，不是“每层新增多少维”，也不是通用最优公式。

### 3.4 词表为什么也是架构选择？

词表越大，通常越有机会把常见字串合成一个 token，使同样文本的序列更短；代价是输入 embedding 和输出打分层会增大。

因此，词表大小同时影响文本压缩与模型参数。多语言模型往往需要覆盖更多文字与常见片段，常选择更大词表。读者可以把它与上一篇连起来：分词器决定模型每步处理什么，架构决定每步怎样计算。

### 3.5 数据很多时，还要防止过拟合吗？

过拟合是模型过度适应训练数据，在新数据上表现却不理想。两种传统对策是 dropout 与权重衰减。

dropout 在训练时随机将部分中间激活置零，推理时关闭。权重衰减则在更新参数时让权重略微向零收缩。

许多大规模预训练采用海量数据，只遍历较少次数，dropout 带来的收益可能变小，因此常把它关闭。不过，训练一遍也不等于绝不会过拟合，微调时的数据规模与使用方式更可能不同。

权重衰减则经常保留。课程引用的实验提示，它除了影响泛化，还会影响优化过程。把这些方法都归结为“防止记住训练集”，不能解释全部现象。

补充｜dropout 与权重衰减的配置数字

用"dropout 概率 / 权重衰减系数"记录：原版 Transformer 为 0.1/0，GPT-2/3 为 0.1/0.1，T5 v1.1 为 0/0，Llama 为 0/0.1，Qwen-14B 为 0.1/0.1。前者 0.1 表示对应激活有 10% 的概率被置零；后者 0.1 是衰减系数，实际收缩幅度还取决于学习率与实现。

Andriushchenko et al.（2023）在所研究的设置中观察到，权重衰减的收益与训练后期的学习率下降有关：学习率变小时，带权重衰减的模型损失下降得更快。这是一项具体实验结论，不表示它在所有任务中都只影响优化、不影响过拟合。

### 3.6 训练不稳定时，为什么会检查 softmax？

训练中，有时参数更新信号会突然变得很大，导致损失陡增。前文的归一化是一类稳定措施，另一些措施专门作用于注意力和输出层的打分。

这两个位置都会用 softmax。它要先对原始分数做指数运算，再归一化为概率，因此需要认真处理数值尺度。实际实现会采用稳定算法；模型本身的分数增长也可能需要额外约束。

理解以下三种方法的作用位置即可：QK-norm在计算注意力分数前调整 Q、K 的尺度；logit 软截断限制原始分数的幅度；z-loss在训练目标中加入一项，约束输出分数的归一化尺度。它们都服务于稳定训练，但并非可以随意互换。

补充｜三种稳定性技巧的具体形式

| 方法 | 操作 | 代表例子 |
| --- | --- | --- |
| QK-norm | 先归一化 Q、K，再计算匹配分数 | ViT-22B、Gemma 3、OLMo 2 |
| logit 软截断 | 用 cap × tanh(logit / cap) 平滑限制分数范围 | Gemma 2 |
| z-loss | 增加 λ × (log Z)²，Z 是 softmax 分母，即指数分数之和 | PaLM、Baichuan 2、OLMo 2 |

z-loss 中 λ 控制约束强度。Q、K 归一化已有较早研究：Henry et al.（2020）将其用于机器翻译，后来的 ViT-22B 等模型也使用相关设计，但归一化形式可以不同；Gemma 3 报告明确说明它用 QK-norm 替换了 Gemma 2 的 soft-capping。两类方法的效果需结合模型、学习率和实验设置判断，某一组消融中的优劣不能直接推广成普遍排序。

## 四、为什么生成长文本越来越贵？

### 4.1 省下重复计算之后，出现了缓存成本

模型生成回答时，通常每次新增一个 token。第二步仍需要读取第一步的文本，第三步需要读取前两步，以此类推。

如果每一步都从头计算所有历史位置，就会反复做相同工作。因此，模型保存各层历史位置已算好的 K、V，下一步只计算新位置的表示。这份保存下来的数据叫KV cache。

缓存减少了重复计算，却占用显存，而且新 token 的注意力仍要读取它。文本越长，缓存越大，每一步需要读取的数据也越多。

以 Llama-2-70B 为例，一个 4096 token 会话的 fp16 KV cache 约为 1.34 GB。多个会话同时生成时，这项占用还会叠加。长上下文的成本，因此既包括运算，也包括存储和搬运。

补充｜这笔 KV cache 显存账怎么算

Llama-2-70B 有 80 层，每层 8 个 KV 头，每头 128 维；fp16 每个数占 2 字节：

```
每 token：80 层 × 2（K、V）× 8 头 × 128 维 × 2 字节 = 327680 字节 = 320 KiB4096 token：约 1.34 GB（1.25 GiB）
```

（仅计 KV 数据，不含权重、临时工作区与分配开销。）GPU 还会受到算术强度限制——每搬运一字节能完成多少次运算。小批量逐 token 生成中数据读取相对多、算术强度低，显存带宽就可能成为瓶颈；具体瓶颈随模型大小、序列长度、批大小和实现变化。

### 4.2 GQA：让多个查询头共享 K、V

既然缓存保存的是 K、V，一个直接思路就是：让多个头共用 K、V，同时保留各自的 Q。

标准多头注意力中，每个查询头都有对应的 K、V。MQA让所有查询头共享一组 K、V；GQA则分成几组，每组内部共享。

例如 64 个查询头各自保留独立 Q，但只使用 8 组 K、V。在相同头维度、层数和精度下，KV cache 就是原来 64 组配置的 1/8。Llama-3-70B 采用的就是 64 个查询头、8 个 KV 头的配置。

共享越多，缓存越小，但表达方式也受到更强约束。GQA 在效果与缓存成本间取得了实用折中，因此被广泛采用；MQA 则进一步共享到只剩一组。

### 4.3 滑动窗口：每一层都需要读取全部历史吗？

除了压缩缓存，还可以减少单层读取的位置数。

滑动窗口注意力让每个位置只读取附近的一段前文。例如窗口为 4096，就把单层直接访问的历史限制在这一范围内。层与层之间仍能传递信息，因此多层叠加后可以间接利用更远的位置，但这不等于能像全局注意力一样直接访问远处内容。

另一种安排是混合局部层与全局层：大部分层只看附近，少数层读取全部历史。这样既保留长距离信息交互，也降低多数层的开销。

补充｜稀疏注意力与交错层的例子

完整注意力要计算许多位置对，整段计算的开销随序列长度平方增长；滑动窗口是结构化稀疏注意力的一种，更一般的稀疏模式还可以选取其他位置组合。课程讨论的 Command A 采用每组 3 个局部滑窗层 + 1 个全局层：局部层用 RoPE，全局层不另加显式位置编码（NoPE）——但全局层接收的表示已经过前面各层处理，不能认为它读到的信息完全没有位置。Mistral、Gemma 等也采用过局部+全局设计，窗口、配比和位置编码方案不同；状态空间模型与注意力的混合是另一条路线，本文不展开。

## 五、MoE：怎样让模型拥有更多参数，却只计算其中一部分？

### 5.1 “总参数”与“激活参数”分开了

前面讨论的普通模型，在计算每个 token 时，会使用各层相同的注意力与 FFN 参数。这类模型通常称为稠密模型。

MoE（Mixture of Experts，混合专家）把部分层的一个 FFN 换成多个 FFN，称为专家。另加一个路由器，为每个 token 选择其中少数专家计算，再混合它们的输出。

这里的“专家”指一组可学习的网络参数。它们不一定分别对应数学、法律、编程等人工指定的领域，分工通常是在训练中形成的。

例如，一个 MoE 层有 8 个大小相同的专家，每个 token 只选 2 个。模型需要存储 8 个专家，但对这个 token 只执行其中 2 个。于是需要区分：

- 总参数量：全部参数都要存下来，主要影响权重存储成本。
- 每 token 激活参数量：当前 token 实际使用哪些参数，主要影响它的计算量。

Mixtral 8×7B 总参数约为 46.7B，每 token 激活约为 12.9B。模型名称不能直接按 8 × 7B 理解，因为注意力等部分由专家共享。

MoE 的吸引力正在这里：保持专家大小和每次选择的数量近似不变，可以增加专家总数，从而增加模型容量，而不同比增加主要 FFN 计算量。额外的存储、路由和通信成本仍需要支付。

### 5.2 路由器怎样选择专家？

路由器根据当前 token 的向量，给每个专家打分，选择分数最高的 k 个。这叫top-k 路由；k 表示每次选几个。

比如有 4 个专家，分数为：

```
专家编号：  1     2     3     4得分：     0.10  0.70  0.80  0.20
```

若 k=2，就只计算专家 2 和 3，再按照门控权重混合两份输出。不同 token 可以选不同专家，同一 token 在不同层也可能得到不同选择。

这与前面 SwiGLU 的门控有联系，但计算方式不同。SwiGLU 调制特征维度，通常仍执行完整的稠密计算；MoE 选择整个专家，未入选专家对当前 token 的计算可以跳过。这就是条件计算：实际执行的计算取决于输入。

补充｜专家选择与输出权重，并不是同一步

路由可分为：计算分数、选出专家、确定输出混合权重，不同模型在分数变换与归一化上的设计不同。上文的示意中，若按入选分数之和归一化，专家 2、3 的输出权重约为 0.467、0.533——这只说明加权过程，不代表所有模型采用同样的打分公式。DeepSeek-V3 用 sigmoid 得到匹配分数，选专家后对入选的原始分数按和归一化（不能写成"再做一次 softmax"）；其负载调整 bias 只影响选择，不加入最终输出混合权重。此外还有哈希路由、专家主动选 token、全局分配等研究方向，本文聚焦常见的 token-choice top-k。

### 5.3 选择是离散的，路由器怎样学习？

模型训练的主目标仍然是减少预测错误。这个目标既训练专家，也需要训练路由器，让它逐渐选出有用的组合。

困难是：“专家有没有入选”是离散选择，无法直接像连续数值一样求导。不过，专家输出所乘的门控权重可以是连续值。

以 Switch Transformer 为例，主任务损失能通过这个连续权重反向传播，更新路由器参数。被选中的专家也会接到梯度，学习怎样改善自己的输出。因此，路由器有来自主任务的学习信号，不是只靠额外的均衡规则工作。

### 5.4 为什么还要负载均衡？

主任务的学习信号并不保证工作分配均匀。假设一批 100 个 token 中，80 个都选了同一个专家：该专家可能成为计算瓶颈，其他专家获得的训练机会也较少。

一种办法是在训练目标里加入负载均衡辅助损失。除了预测错误，模型还会因负载过度集中受到额外约束。约束太弱，专家可能失衡；太强，又可能妨碍路由器选择对任务最有用的专家。

DeepSeek-V3 的另一种做法是动态调整选择分数：负载较高的专家降低选择偏置，较低的提高。这样能改变分配，又不把这部分均衡要求直接加入主任务的梯度。

这解释了“auxiliary-loss-free（免辅助损失）”这个名称。V3 实际仍保留了较小的序列级辅助损失，用于防止单个序列内的极端失衡；不能把名称理解为完全没有辅助损失。

补充｜Switch Transformer 的平衡损失公式

```
辅助损失 = α × E × Σᵢ fᵢPᵢ
```

E 是专家数，fᵢ 是专家 i 实际接收的 token 比例，Pᵢ 是路由器分给它的平均概率，α 控制约束强度——已被大量选中的专家若继续得到较高平均概率，就会增大这项损失。离散的 fᵢ 不直接求导，可微的 Pᵢ 提供更新信号；这个公式解决的是负载均衡，与主任务通过门控权重训练路由器的作用不同。DeepSeek 早期 MoE 还约束设备级负载：专家分布在不同卡上时，只让专家之间均衡，未必能让各张卡的实际工作量也均衡。

### 5.5 专家越多越好吗？

增加专家之前，至少需要考虑三个边界。

首先是存储。每次只选两个专家，也不意味着其余专家可以从模型中删除。高吞吐部署通常将全部专家参数分布到多张卡的显存中；若把参数卸载到其他存储，又会引入搬运成本。

其次是通信。某个 token 选中的专家可能不在本卡上，它的中间表示需要发送过去，专家输出再传回来。这类设备间的数据交换称为 all-to-all 通信。实际运行时间因此不会只由激活参数量决定。

最后是训练数据与优化。专家得到的训练机会不够，新增参数就未必带来预期收益。MoE 的效果取决于数据量、路由、专家大小与训练预算。

一个进一步的设计是把专家切小：例如用更多小专家替代少数大专家，每个 token 也相应选择更多个。在主要 FFN 计算量近似不变时，可以获得更灵活的组合。另一些模型还设置共享专家，让所有 token 都经过它们，承担一部分公共变换。

补充｜细粒度、共享专家与配置对照

把 16 个专家、每次选 2 个，改成 64 个四分之一大小的专家、每次选 8 个，主要 FFN 计算量近似不变，可选组合数从 120 增至约 44 亿——组合数增加不等于模型一定学会这么多分工，收益仍要实验验证。DeepSeek 的实验支持细粒度与共享专家；OLMoE 的消融支持细粒度，但未观察到共享专家的同样收益，说明配方不能直接移植。

| 模型 | 路由专家数 | 每 token 选中数 | 共享专家数 | 备注 |
| --- | --- | --- | --- | --- |
| GShard | 2048 | 2 | 0 | 早期极端多专家 |
| Switch Transformer（一种配置） | 64 | 1 | 0 | k=1 的激进简化 |
| Mixtral 8×7B | 8 | 2 | 0 | 46.7B / 激活 12.9B |
| DBRX | 16 | 4 | 0 | 细粒度先行者之一 |
| Grok-1 | 8 | 2 | 0 | 314B 总参数 |
| DeepSeekMoE V1 | 64 | 6 | 2 | 16B / 激活 2.8B，细粒度 1/4 尺寸 |

共享专家不包含在"选中路由专家"的数量里；统计激活参数时需算上它们，以及模型中的注意力和其他稠密部分。

补充｜实现与微调还会遇到的坑

容量与 token dropping。一些实现为每个专家设容量上限，超出容量的 token 跳过该专家、走残差路径继续传播——输出因此受同批其他 token 分配的影响；但并非所有 MoE 都这样处理，DeepSeek-V3 报告明确说明训练与推理均不丢弃 token。

路由精度。较小的分数变化可能改变 top-k 结果，路由常需更高精度；部分训练方案还用 router z-loss 约束打分尺度。

微调。小数据微调可能让 MoE 过拟合，已有工作尝试冻结部分专家层、调整正则化或增加数据，应按具体任务验证。

Upcycling（稠密转稀疏）。用已训练的稠密 FFN 复制初始化多个专家，再加路由器继续训练。公开案例既有成功（MiniCPM-MoE；Qwen1.5-MoE——课程称其为"首批被确认成功的 upcycling"），也有相反结论：OLMoE 的对照实验中，从零训练的 MoE 在约 500–600B token 处反超 upcycling 版本；另一脉工作（Komatsuzaki et al.）则报告从零训练要多花约 120% 算力才追平。结论强依赖于路由方式与设置，未有定论；是否划算还取决于比较时是否计入稠密模型原先的训练成本。

### 5.6 进阶案例：DeepSeek 的配方怎样演进？

理解前面五节后，再看 DeepSeek 的变化，就不再是一串独立名词：细粒度与共享专家解决容量组织，设备限制解决通信，负载均衡解决分配。

| 阶段 | 总参数 / 激活 | 专家配置 | 每代新增 |
| --- | --- | --- | --- |
| DeepSeekMoE V1 | 16B / 2.8B | 64 个 1/4 尺寸专家选 6，加 2 共享 | 细粒度 + 共享专家；专家级 + 设备级双重辅助损失 |
| DeepSeek-V2 | 236B / 21B | 160 个 1/10 尺寸专家选 6 | 通信平衡损失；top-M 设备受限路由 |
| DeepSeek-V3 | 671B / 37B | 256 个 1/14 尺寸专家选 8，加 1 共享 | sigmoid 打分 + 按和归一化；auxiliary-loss-free（bias 在线调整）+ 序列级辅助损失 |

配置数字可以查表，主线是：专家增加以后，存储、通信和负载分配必须一起设计。

### 5.7 MLA 与 MTP：分别解决另外两个问题

MoE 主要改变 FFN。完整模型还要处理注意力缓存，以及训练时怎样利用数据。这分别引出 MLA 和 MTP。

MLA（多头潜在注意力）压缩的是 KV cache。GQA 通过减少 KV 头数节省缓存，MLA 则学习更紧凑的低维表示，缓存压缩后的信息，供后续注意力计算使用。它与 MoE 作用在不同组件上，不能相互替代。

MTP（多 token 预测）增加的是训练监督。普通训练在每个位置预测下一个 token；MTP 增加对更后面 token 的预测目标，希望同一段数据提供更丰富的学习信号。它也可以配合投机解码：先提出多个候选 token，再由主模型验证，以减少逐步生成的延迟。

补充｜MLA 与 MTP 的实现边界

MLA 的压缩表示要与位置编码配合设计：DeepSeek把部分位置相关的表示分离出来处理RoPE，其余走低维压缩；优化实现还会把部分投影合并进后续计算，不能认为每一步都必须完整解压全部历史 K、V。

DeepSeek-V2报告相对DeepSeek-67B给出了 KV cache 减少 93.3%、训练成本降低42.5%、最大生成吞吐提高5.76倍的整体比较—缓存收益与MLA密切相关，但训练成本与吞吐也受MoE、模型配置和系统实现影响，不能全部归功MLA。DeepSeek-V3 的MTP深度为 1：在主模型的下一token预测之外再增加一个未来token的预测目标，采用带因果链的额外预测模块（不只是几个相互独立的输出头）；推理时可以移除MTP模块，也可以将其用于投机解码。

## 六、把两讲连起来

现在可以把模型的设计选择放回同一条计算过程。

token 先变成向量。注意力读取上下文，RoPE 为匹配加入相对位置信息；FFN 加工当前位置的表示，门控让特征之间产生更灵活的交互。残差连接与归一化帮助多层模型稳定训练。

开始生成文本后，历史 K、V 被缓存。GQA、滑动窗口和 MLA 从不同方向降低缓存或注意力开销。若还想在相近的主要计算量下增加容量，MoE 则让每个 token 只计算少数专家，同时带来参数存储与通信的新要求。

| 想解决的问题 | 本文讨论的设计 |
| --- | --- |
| 深层模型怎样稳定训练 | 残差、pre-norm、归一化、打分尺度约束 |
| 每个位置怎样加工信息 | FFN 宽度、激活函数、门控 |
| 注意力怎样利用位置 | 位置编码、RoPE |
| 长文本生成怎样控制成本 | KV cache、GQA、滑动窗口、MLA |
| 怎样增加容量又控制主要计算量 | MoE、路由、负载均衡 |

第 3 讲展示的是成熟架构中的常见选择与取舍，第 4 讲展示的是条件计算带来的新空间。读懂配置的关键，是能说清它改变了哪一步计算、节省了什么，又新增了什么成本。

## 追问清单（附答案）

## 1. Pre-norm 更常见，为什么 BERT 还能用 post-norm？

post-norm 仍然可以训练，BERT 使用的学习率预热就是稳定措施之一。归一化位置的效果还取决于模型深度、初始化和学习率安排；pre-norm 更常见，并不表示其他配置必然失效。“双重归一化”也要看具体结构：子层分支上的输出归一化，与残差相加后的主干归一化，作用位置不同，不能仅凭名称判断。

## 2. 比较门控效果时，为什么要对齐参数量与计算量？

如果换结构时也增加了参数与计算，就很难单独判断门控贡献了多少。2.3 节的 8/3 倍来自对齐主要矩阵参数量的计算。未对齐的实验仍可用于比较实际效果与成本，但归因时需要报告预算差异；实际模型也无需固定采用 8/3。

## 3. RoPE 为什么只旋转 Q、K，不旋转 V？长上下文外推怎么办？

RoPE 要在 Q、K 的匹配中引入相对位置，因此不需要旋转作为读取内容的 V。处理更长文本则是另一项训练与验证任务：位置缩放、基频选择和继续训练都可能参与，不能只改窗口上限就假设效果不变。

Llama 3 报告列出的 RoPE 基频参数是 50 万，并说明 405B 模型经过六个阶段，将上下文从 8K 逐步扩到 128K。这体现了位置配置与长上下文训练的配合。4.3 节提到的 Command A 则已于 2025 年发布，其全局层不另加显式位置编码，是另一种架构选择。

## 4. MoE 只计算部分专家，为什么部署仍然贵？

少算不等于少存。以相同权重精度比较，Mixtral 46.7B 的权重存储仍接近一个 47B 稠密模型。高吞吐部署通常把专家放在多卡显存中，需要支付通信成本；也可以将部分参数卸载到其他存储，但会增加搬运与等待。是否划算，应比较同等质量下的实际显存、吞吐和延迟。

## 5. 用来均衡负载的 bias，会不会改变专家输出的混合权重？

在 DeepSeek-V3 的设计里，bias 只用于决定哪些专家入选；最终混合权重仍由入选专家未经 bias 调整的匹配分数归一化得到。它改变的是选择，而非直接给某个专家的输出加权。至于“免辅助损失”的限定，见 5.4 节：模型仍保留序列级辅助损失。

## 6. 实际部署时，MLA 和 GQA 应该怎样比较？

两者都能减少缓存，但采用不同的表示方式。比较时要同时固定或报告模型质量、上下文长度、并发量和数值精度，再测缓存占用、吞吐与延迟，并检查推理框架是否充分优化了相应算子。理论压缩率提供了方向，实际部署收益仍需要测量。
